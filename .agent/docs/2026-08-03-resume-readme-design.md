# Infinity Craft 简历展示型 README 设计

> 文档日期：2026-08-03

## 目标

将仓库主页从偏内部运维的长篇说明，改造成面向 HR 与 AI 应用开发岗位面试官的产品案例页。读者应能在 30 秒内理解产品创意、AI 的作用、项目完成度，以及作者从创意到上线的综合能力。

## 叙事策略

采用“产品案例型”结构，以产品价值开场，以真实界面建立可信度，再逐层展示 AI 工作流、完整功能、双运行时架构和工程化能力。运行维护细节保留必要入口，其余链接至现有开发文档。

README 使用中文为主，语气专业、克制，不虚构用户量、性能数字、在线地址、许可证或测试状态。

## 信息结构

1. Hero：项目名、一句话定位、技术标签、页内导航和游戏主页截图。
2. 项目概览：说明创意、AI 生成和社区竞争形成的产品闭环。
3. 核心体验：展示元素合成、昵称身份、全球首发、首发墙、排行榜、分数等级和隐藏玩法。
4. AI 工作流：解释预设配方、缓存、未知组合模型生成、结构化校验与 fallback。
5. 工程亮点：强调从产品设计到前后端、数据层、测试和生产部署的完整落地。
6. 系统架构：对比 FastAPI + Redis + SQLite 本地环境与 Makers Edge Functions + KV + Models 生产环境。
7. 技术栈：按前端、后端、AI、存储、部署和测试分类。
8. 快速开始：保留最短可执行流程、访问地址和无 Key 行为。
9. 深入开发：链接完整开发指南、后端词库说明及验证命令。
10. 项目背景与致谢：注明灵感来源，避免将衍生创意表述为原创玩法。

## 图片编排

- `docs/imgs/游戏主页.png`：Hero 下方宽幅主视觉。
- `docs/imgs/游戏入场选名字.png`、`docs/imgs/合成中.png`、`docs/imgs/全球首发.png`：使用 HTML 表格并排展示“身份—生成—反馈”交互闭环。
- `docs/imgs/首发墙.png`：核心体验后半段的宽幅社区与排行榜展示。

图片使用仓库相对路径和有意义的替代文本。保持原图，不生成概念图，不裁切功能信息。GitHub 窄屏下允许表格横向滚动，单张宽图由渲染器自动缩放。

## 内容边界

- 不声明尚未提供的线上演示地址；预留一句可被未来链接替换的说明没有价值，因此不放占位符。
- 不显示仓库不存在的 License、CI 或构建状态徽章。
- 不把 README 写成简历自述，不使用“我负责”等无法从仓库验证的表述；通过功能、架构和工程决策自然体现能力。
- Makers 控制台变量、KV 一致性细节、Icon 生成维护和历史 Render 配置移至现有开发文档承载。
- 保留安全提醒：密钥只放 `.env`，不得提交。

## 验证

- 检查所有相对链接与图片路径存在。
- 检查 README 不含占位符、失效锚点或未经验证的指标。
- 运行 Markdown 结构检查；项目代码未变化时无需用测试结果冒充 README 验证，但会运行仓库要求中与文档改动相称的现有检查。
