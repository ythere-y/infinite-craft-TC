# 普通模式默认启动与顶栏切换按钮设计

## 目标

游戏首次打开时保持普通模式。玩家既可以输入
`↑↑↓↓←→←→BA`，也可以点击顶栏按钮，在普通模式和里模式之间
双向切换。

## 范围

### 包含

- 将里模式初始化默认值恢复为关闭。
- 在顶栏现有操作按钮组中、帮助按钮之前增加模式切换按钮。
- 普通模式下按钮显示“🌙 里模式”，点击后进入里模式。
- 里模式下按钮显示“☀️ 普通模式”，点击后返回普通模式。
- 保留现有键盘秘籍、进退场动画、筹码状态和两种模式的计分规则。
- 同步按钮的可见文字、提示文字和无障碍状态。

### 不包含

- 持久化玩家上次选择的模式。
- 修改里模式动画、视觉主题或计分规则。
- 移除键盘秘籍或顶栏里模式状态横幅。

## 状态与交互

`frontend/effects.js` 继续作为模式状态的唯一来源。它对外提供一个
切换方法，顶栏按钮和键盘秘籍都调用该方法，避免出现两套互相独立的
状态。

`EFFECTS.initBossMode()` 默认只安装事件监听，不开启里模式。首次加载
不添加 `body.ura-on`，不显示里模式横幅，不播放动画，也不发送一次
虚假的进入事件。

玩家手动进入或退出模式后，现有 `ura-mode-change` 事件携带最终状态。
按钮监听该事件并更新自身：

- 普通模式：显示“🌙 里模式”，提示点击进入，`aria-pressed="false"`。
- 里模式：显示“☀️ 普通模式”，提示点击退出，`aria-pressed="true"`。

按钮初始化时直接读取 `EFFECTS.isUraMode()`，因此不依赖首次模式事件。
模式切换动画期间，状态仍以 `EFFECTS.isUraMode()` 返回值为准。

## 页面与样式

按钮使用现有 `.btn-ghost` 视觉语言，并放在 `.topbar-actions` 中帮助按钮
之前。模式图标使用文字 emoji，不依赖新增图标资源。

桌面端显示图标和完整文字。窄屏沿用顶栏的紧凑规则，只保留模式图标，
但通过 `aria-label` 和 `title` 保留明确语义。里模式下按钮使用现有暗色
顶栏按钮样式。

## 错误与边界

- 重复调用初始化不会重复绑定键盘或按钮事件。
- 按钮不存在时，键盘秘籍仍可正常使用。
- 按钮点击与秘籍交替使用时，均从当前真实状态切换。
- 从里模式退出不会清空未收获筹码；再次进入后继续现有回合。

## 测试

浏览器回归测试覆盖：

- 首次加载处于普通模式，没有入场动画或初始进入事件。
- 初始按钮显示“🌙 里模式”且未按下。
- 点击按钮进入里模式，按钮变为“☀️ 普通模式”并标为按下。
- 再次点击按钮返回普通模式。
- 键盘秘籍仍能往返切换，并同步按钮状态。
- 手动再次进入里模式时仍保留现有进场动画。

现有赌场控制器测试继续验证里模式筹码和收获逻辑。完成后运行仓库要求的
`npm test`、`python3 -m pytest tests --ignore=tests/test_combine_feedback.py -q`
和 `npm run build`。

## 验收标准

- 新会话默认显示普通模式。
- 顶栏模式按钮始终说明点击后要进入的目标模式。
- 按钮和键盘秘籍均可在两种模式之间反复切换。
- 所有入口共享同一状态，视觉、计分与按钮文案保持一致。
- 项目规定的测试和构建命令通过。
