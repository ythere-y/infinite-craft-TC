# QQ 时代经典图标与合成路径设计

## 背景

“QQ时代记忆”包含 44 个元素。当前部分新增元素仍使用通用 emoji
作为主体，并附加与业务无关的随机角标。例如黄钻、黑钻等被表达为不同颜色
的心形，无法唤起对应的经典产品记忆，也造成明显的视觉同质化。

本项目只用于内部测试，允许将找到的腾讯历史素材保存到项目内使用。本次
恢复优先采用 2008–2012 年 PC QQ 时代最具辨识度的版本。

## 目标

- 为 44 个元素分别提供语义明确且唯一的图标。
- 优先恢复腾讯官方或可信历史来源中的经典原图。
- 找不到合格原图时使用项目已有图标库，不进行手工或 AI 重绘。
- 清除随机角标；组合图标的每个组成部分都必须表达元素含义。
- 让所有 44 个元素拥有预设合成配方，并能从开局元素严格到达。
- 通过自动化报告同时验证素材完整性、图标重复度和配方可达性。

## 非目标

- 不为经典素材制作新的品牌诠释或现代化改版。
- 不在运行时从第三方网站加载图片。
- 不让玩家数据库或 LLM 临时结果成为预设可达性的必要条件。
- 不要求基础合成元素同时出现在悬赏榜单中。

## 素材来源策略

来源优先级固定如下：

1. 腾讯官方历史页面、腾讯 ISUX 文章或官方品牌素材。
2. 历史客户端资源、可信网页存档或可核验的旧版图标包。
3. 项目现有图标库中的语义相关图标。

同一服务存在多代素材时，选择 2008–2012 年最具辨识度的一代。素材清单
记录元素名、本地文件、原始网址、年代、来源类型和备用图标。浏览器只加载
已经进入项目的本地资源。

已确认可作为官方视觉依据的资料包括：

- 腾讯 ISUX《QQ大会员品牌运营策划与设计》：
  https://isux.tencent.com/articles/big-vip-1th.html
- 腾讯 ISUX《破局升级 | QQ VIP官网再设计》：
  https://isux.tencent.com/articles/qq-vip-redesign
- 腾讯 ISUX《VIP品牌升级 | 打造有温度的二次元形象》：
  https://isux.tencent.com/articles/qzonevip-qqvip-ipdesign.html

这些资料明确保留了 QQ会员、超级会员、空间黄钻和豪华黄钻的独立视觉
体系，可用于纠正现有“彩色心形加随机角标”的错误表达。

## 图标架构

每个经典元素绑定一个独立的本地图片资源。QQ 时代素材放入专用目录，并
通过现有元素图标映射接口加载。映射可以引用本地品牌素材标识，也同时保存
一个由现有图标库组成的确定性备用方案。

构建流程先验证品牌素材。如果文件存在、能解码且适合显示，就将品牌素材
写入最终清单；否则写入对应的备用方案。前端加载本地图片发生意外错误时，
立即切换到同一元素预先指定的备用图标，不显示破图、缺图占位符或随机
emoji。

所有经典素材和备用图标都必须离线可用。生产和本地运行都不依赖素材来源
网站。

## 素材失败与回退

以下任一情况触发现有图标库回退：

- 没有找到可以核验的历史素材；
- 图片内容不对应目标产品；
- 文件损坏、无法解码或透明区域异常；
- 裁切后主体不可辨认；
- 游戏实际显示尺寸下无法清楚辨识；
- 构建时本地文件缺失。

回退是逐元素预先配置的确定性结果。它不能随机选择角标，也不能因为重新
执行生成脚本而变化。前端运行时的图片加载错误采用同一备用方案。

## 合成配方与可达性

使用现有 `scripts/trace_recipe.py` 计算从 starter 出发的严格可达性和最短
路径。验收时关闭玩家数据库与 LLM 合并，确保结论只依赖随项目初始化的
预设内容。

对于不存在或不可达的 QQ 时代元素：

1. 将元素登记为基础支持元素；
2. 将直接配方加入内容目录的 `support_recipes`；
3. 确认配方的两个输入本身均严格可达；
4. 重新生成编译内容并再次计算最短路径。

合成配方以语义合理、路径长度适中和复用已有基础元素为原则。新增支持元素
不要求属于悬赏榜单，但必须随基础数据库初始化，而不是等待玩家触发 LLM
生成。

最终可达性报告必须列出每个目标的直接配方、最短深度和完整最短路径，并且
44 个目标全部通过。

## 自动化验收

图标检查覆盖：

- 44/44 元素都有经典素材或备用方案；
- 每个本地文件存在且可解码；
- 每个备用图标都能通过现有图标清单解析；
- 最终映射组合全部唯一；
- 检测完全相同的文件、完全相同的映射和异常高视觉相似度；
- 七钻系列只豁免合理的家族相似，不豁免完全重复；
- 报告标明经典素材、库内回退和回退原因。

配方检查覆盖：

- 44/44 元素存在直接预设配方；
- 44/44 元素从 starter 严格可达；
- 每条新增配方的输入均严格可达；
- 生成内容与后端、Edge 运行时数据一致。

完成实现后运行项目规定的验证：

```text
npm run audit:icons
npm run verify:icons
npm test
python3 -m pytest tests --ignore=tests/test_combine_feedback.py -q
npm run build
```

此外，以 `--no-llm` 模式批量运行配方追踪脚本，并保存 44 个目标的报告。

## 本地交付

验证通过后使用项目现有 Docker 开发流程启动游戏，检查
`http://127.0.0.1:8000/api/health`，再向测试者提供局域网
`IP:8000` 地址。测试者无需 EdgeOne 登录，也不依赖外部素材服务器。

## 验收标准

- QQ 时代榜单显示 44 个经过逐项策划的图标。
- 黄钻、黑钻及其他钻石不再显示为彩色心形或带无关角标。
- 经典素材失败时稳定显示指定的现有库图标。
- 44 个最终图标映射没有完全重复。
- 自动报告中 44 个目标全部拥有直接配方并严格可达。
- 本地游戏可通过局域网 IP 和端口访问。
