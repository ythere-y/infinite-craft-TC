# 本地 Prompt 配置与版本管理设计

## 背景

Issue #22 的目标是让本地部署版本的合成 Prompt 可以直接编辑，不再要求每次调整都修改源代码。
目前，Prompt 定义在 `shared/combine-prompt.json` 中，由 Python 后端负责渲染，并在构建时转换为
Makers 使用的静态数据。本地 `/admin` 页面目前只提供运行监控，并已支持通过可选的
`ADMIN_TOKEN` 进行访问保护。

本次改动只面向本地 FastAPI 部署。Makers/EdgeOne 仍在构建时使用仓库中的静态 Prompt 规范。

## 目标

- 在 `/admin` 中管理固定 Prompt 模块、风格指令及概率、正面案例、负面案例和现有 Prompt 参数。
- 将可编辑草稿与线上 LLM 实际使用的版本分开。
- 聚合草稿时，根据配置概率选择一个已启用风格，生成不可变且可预览的 Prompt 版本。
- 管理员审核后显式启用版本，并可回滚到任意历史版本。
- 将草稿、历史版本和当前生效版本指针持久化到本地 SQLite。
- 首次升级时，将现有标准 Prompt 自动导入为初始草稿和初始生效版本，保证升级前后的
  LLM 行为不变。
- 所有 Prompt 管理读写操作都必须通过 `ADMIN_TOKEN` 鉴权。
- 为以后接入社区正面和负面案例保留扩展点，但本次不实现 issue #2 的社区治理功能。

## 不在本次范围内

- 社区投票或公式治理。
- 自动导入社区高分或低分公式。
- 模型微调。
- 云端多租户 Prompt 管理。
- Makers/EdgeOne 运行时 Prompt 管理。
- 富文本编辑器或可视化 Prompt 工作流编排器。
- 删除历史 Prompt 版本。

## 选定方案

在 SQLite 中保存一份经过校验的 JSON 草稿，并将每次聚合结果保存为不可变 JSON 快照。
另用一条单例状态记录指向当前生效版本。

没有选择为风格、案例和模块分别建立大量关系表，是因为配置总是作为一个整体读取和校验；
整体原子保存也能避免只更新了一部分配置的中间状态。没有选择直接写 JSON 文件，是因为
SQLite 能提供事务、可靠的容器数据卷持久化，以及天然的不可变版本历史。

## 数据模型

SQLite 保存三类逻辑记录：

1. 单例 Prompt 草稿：包含经过校验的模块化配置和更新时间。
2. 不可变 Prompt 版本：包含稳定版本标识、创建时间、所选风格的标识和名称、完整配置快照、
   实际生效的 Prompt 规范以及渲染后的预览文本。
3. 单例生效状态：指向一个已存在的 Prompt 版本。

草稿包含：

- Schema 版本和 temperature；
- 带稳定 ID、启停状态、顺序和内容的固定系统模块；
- 带稳定 ID、启停状态、名称、指令和百分比概率的风格；
- 可启停的正面纯文本案例；
- 可启停的负面纯文本案例；
- 为保持兼容而保留的现有结构化 few-shot 案例；
- 现有容量参数和 Prompt 限制参数。

已生成版本不允许原地编辑。启用或回滚版本时，只在一个事务内更新当前生效版本指针。

## 首次导入与兼容性

本地数据库初始化时，如果不存在 Prompt 管理数据，则执行一次性导入：

1. 加载并校验 `shared/combine-prompt.json`。
2. 将原有风格的小数权重转换为百分比。
3. 保留所有现有模块、结构化案例、参数和渲染行为。
4. 建立空的手动正面和负面纯文本案例集合。
5. 将转换后的配置保存为初始草稿。
6. 生成一份代表原标准规范的初始不可变版本，并将其设为生效版本。

初始化过程必须具备幂等性。后续启动不得覆盖数据库中已经存在的配置。如果持久化数据无效
或损坏，服务应明确报错，不得静默回退到另一份 Prompt。

本地 Python LLM 调用链读取当前生效版本。Makers 静态构建继续读取
`shared/combine-prompt.json`，因此本地管理功能不会给云端引入数据库依赖。

## 校验与聚合

草稿校验会拒绝以下情况：

- 没有任何已启用风格；
- 已启用风格的概率之和不等于 100%；
- 概率不是数字、为负数或大于 100%；
- ID 为空或重复；
- 风格名称或风格指令为空；
- 已启用的固定模块或文本案例内容为空；
- temperature、容量或限制参数无效；
- 结构化案例格式错误。

概率计算采用十进制安全校验，避免浮点误差导致页面显示为 100%，后端却判断不等于 100%。

聚合流程：

1. 读取并重新校验已保存的草稿。
2. 根据百分比概率，从已启用风格中选择且只选择一个风格。
3. 生成实际生效的不可变 Prompt 规范，其中包含已启用固定模块、所选风格指令、已启用正面
   文本案例、已启用负面文本案例、结构化案例和有效参数。
4. 使用有代表性的占位输入渲染完整预览，让管理员能清楚看到所有生效的静态 Prompt 内容。
5. 在一个事务中保存草稿快照、所选风格信息、实际 Prompt 规范和预览文本。
6. 返回该版本供管理员审核，但不修改当前生效版本指针。

管理员在聚合后继续编辑草稿，不会改变已经生成的预览版本。发布新的草稿修改前，必须重新聚合。

## Admin API

所有 `/api/admin/prompt/*` 接口都必须使用与现有监控后台相同的 Bearer
`ADMIN_TOKEN`。

- `GET /api/admin/prompt/config`：返回草稿、当前生效版本摘要和历史版本摘要。
- `PUT /api/admin/prompt/config`：校验并原子替换完整草稿。
- `POST /api/admin/prompt/aggregate`：生成并保存一个待审核预览版本。
- `GET /api/admin/prompt/versions/{version_id}`：返回某个版本的不可变快照和预览。
- `POST /api/admin/prompt/versions/{version_id}/activate`：原子启用一个已存在的有效版本。

鉴权失败返回 `401`；配置校验失败返回 `422`，并提供明确的中文字段错误；版本不存在返回
`404`。持久化状态损坏时应明确返回服务错误并记录日志，但日志中不得包含密钥或完整私有
Prompt 内容。

## Admin 用户界面

`/admin` 增加“运行监控”和“Prompt 管理”两个一级页签，并共享同一个仅在会话期间保存的
Bearer Token。

Prompt 管理页包含：

- 当前生效版本信息和查看操作；
- 可排序、可启停的固定模块编辑器；
- temperature、容量和 Prompt 限制字段；
- 可新增、编辑、删除、启停及设置百分比的风格列表，并实时显示已启用风格概率总和；
- 可新增、编辑、删除和启停的正面及负面纯文本案例列表；
- 明确的草稿保存操作；
- 聚合操作和完整 Prompt 预览；
- 明确的预览版本启用操作；
- 只读历史版本列表，以及查看和重新启用操作。

错误应显示在对应配置区域，并同时提供本次操作的错误摘要。前端不得静默修正非法概率。
可能破坏草稿内容的操作必须由管理员明确触发；历史版本始终保留，可用于恢复。

## 运行时数据流

一次在线合成请求的流程如下：

1. 服务从本地 Prompt 存储中读取当前生效版本。
2. 使用该版本中的限制参数，选择运行时社区案例和规避词。
3. 将当前生效规范传给现有 Prompt 渲染器。
4. 通过现有 LLM 适配器发送渲染后的消息。

草稿修改和已聚合但尚未启用的版本都不会进入在线调用链。

## 测试

自动化测试覆盖：

- 一次性初始化，以及初始 Prompt 渲染行为不变；
- 初始化幂等性，以及重新初始化存储后配置仍然存在；
- 所有 Prompt 管理接口的鉴权；
- 有效草稿的读写，以及各类校验失败；
- 通过注入随机值，确定性验证概率区间边界；
- 聚合快照不可变，以及预览内容完整；
- 显式启用、历史版本回滚和版本不存在错误；
- 在线合成读取当前生效版本，而不是草稿；
- Admin 页主要控件、错误展示和 API 调用；
- 未修改的标准静态 Prompt 继续保持 Python/Makers 渲染一致性。

创建 PR 前，分支必须通过：

```text
npm test
python3 -m pytest tests --ignore=tests/test_combine_feedback.py -q
npm run build
```

装有 EdgeOne CLI 的部署维护者还可以额外运行 `npm run makers:build`。

## 运行安全

- 不提交 `.env`、凭据、SQLite 运行数据或其他生成的运行时数据。
- Prompt 写入使用现有本地 SQLite 存档，不使用 Makers KV。
- `ADMIN_TOKEN` 只沿用现有的浏览器会话存储方式，不写入长期存储，也不记录到日志。
- PR 以 `upstream/main` 为目标，但只有在需求方完成手动测试并明确确认后才能合并。
