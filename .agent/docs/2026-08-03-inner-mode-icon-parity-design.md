# 里模式与普通模式图标一致性设计

## 目标

让普通模式和里模式使用完全相同的元素视觉语义：

- 元素名称相同；
- 主图标相同；
- 角标相同；
- 元素类别与贴纸倾斜角度相同；
- “基础元素”“全球首发”“我的新发现”“拖拽中”和“合成目标”等状态标记相同。

两种模式只保留以下差异：

- 普通模式使用白天主题，里模式使用暗夜主题；
- 普通模式沿用现有稀有度计分，里模式沿用午夜筹码赌桌的收获、连胜和失败规则。

## 当前问题

共享图标系统已经为普通模式提供 `base + badge + palette` 贴纸，但
`frontend/effects.js` 在里模式开启时仍会扫描元素，并把贴纸内部替换为随机
emoji。这个替换流程还需要 MutationObserver、原始 payload 缓存和退出时重绘，
导致同一个元素在两种模式中的图标含义不一致。

文字当前保持真实名称，不需要另建暗夜文字数据或映射。

## 方案

共享图标 renderer 是两种模式唯一的元素渲染来源。里模式切换只负责：

1. 切换 `body.ura-on`；
2. 显示或隐藏里模式指示和午夜牌桌；
3. 派发既有 `ura-mode-change` 事件；
4. 保持既有进退场效果及音效。

删除随机图标池、元素扫描、MutationObserver、原始 payload 缓存、恢复重绘和
`reapplyUra` 接口。普通模式与里模式不再因主题切换而重建元素 DOM。

## 暗夜图标主题

在共享图标样式中使用 `body.ura-on` 上下文选择器，为现有六类 palette 提供
暗夜配色：

- `nature`
- `product`
- `office`
- `studio`
- `people`
- `place`

暗夜主题只覆盖贴纸背景、白色描边、阴影、badge 底色与边框，以及需要在深色
背景上提高对比度的状态标记。图标素材路径、名称文本、badge 素材、palette
类别、尺寸和旋转值不变。

暗夜颜色继续体现六类 palette 的差异，但降低亮度并提高与午夜工作区的边界
对比度。全球首发的金色、个人新发现的紫蓝色、合成目标的蓝色和基础元素的
绿色语义保持不变。

## 数据流和边界

元素创建或刷新时仍由现有 `ICON_SYSTEM.renderElement` 读取元素 payload，
解析已保存或预设的图标配方并生成 DOM。主题切换不参与数据解析。

```text
元素 payload
    ↓
ICON_SYSTEM.renderElement
    ↓
同一份名称、主图标、角标与状态 DOM
    ↓
普通模式 CSS / body.ura-on 暗夜 CSS
```

本次不修改后端图标数据、生成资源、元素合成逻辑、总分存储、普通模式计分或
午夜筹码规则。

## 兼容与失败处理

- 图标资源缺失或加载失败时，继续使用共享 renderer 现有的原生 emoji fallback。
- 切换模式时不重绘元素，因此不会引入额外的网络请求、异步恢复或中间空白。
- 新出现的侧栏元素、画布元素、合成结果、首发 toast 和配方图鉴元素自然通过
  同一个 renderer 获取正确图标；不再依赖里模式观察器补绘。
- 现有 Konami 指令、默认进入里模式、进退场动画及
  `ura-mode-change` 事件保持兼容。

## 验证

新增或更新自动化测试，覆盖：

1. 同一元素在普通模式、里模式和切回普通模式后，名称、主图标 URL、badge
   URL、palette 和状态 class 完全一致；
2. 开启里模式后贴纸背景、边框或阴影使用暗夜主题值；
3. 模式切换前后画布元素的坐标和尺寸不变；
4. 里模式中新创建的元素直接显示共享 icon，而不是随机 emoji；
5. `effects.js` 不再包含随机图标池、MutationObserver 或元素重绘接口；
6. 既有午夜筹码计分测试继续通过。

完成实现后运行项目要求的验证：

- `npm test`
- `python3 -m pytest tests --ignore=tests/test_combine_feedback.py -q`
- `npm run build`

由于本次会修改被项目要求忽略的
`tests/test_combine_feedback.py` 对应测试，另外单独运行相关测试文件，以覆盖
图标主题切换行为。
