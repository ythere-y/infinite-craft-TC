# 画布配方连线设计

## 目标

当画布上同时存在多种元素时，用轻微、流动的连线展示玩家已经发现的合成关系。连线必须满足：

- 只有玩家亲自合成并记录到本地配方图鉴的元素组合才会连线。
- 同一已发现配方在画布上有多个元素实例时，绘制全部有效实例组合，允许形成密集的关系网。
- 线条强度使用玩家最近一次合成该配方时取得的全球合成次数快照。
- 全球合成次数不要求实时刷新；再次合成相同配方时更新快照。
- 视觉始终弱于元素卡片和合成反馈，不干扰拖放、双击或点击。

## 方案选择

采用工作区内的原生 SVG 覆盖层，不引入 React 或 WebGL 运行时。

SVG 路径适合当前基于 DOM 定位的元素：可以直接使用元素的画布坐标生成贝塞尔曲线，支持描边、虚线流动和柔光滤镜，并且容易在拖动时批量更新。Canvas 虽然适合更大的连接数量，但样式调试和自动化测试成本更高；逐条 DOM 直线则不利于弯曲路径和流动高光。

视觉语言参考 React Bits 的 Threads、Floating Lines 和 Line Waves：使用克制的曲线、低透明度底线与缓慢移动的能量高光。只借鉴表现方式，代码使用项目现有的原生 JavaScript 与 CSS。

## 数据契约

### 合成响应

FastAPI 与 Makers 的成功合成响应都新增：

```json
{
  "hit_count": 8
}
```

`hit_count` 表示当前配方完成本次合成后的近似全球累计成功次数。

- 非 fallback 合成对该配方的全局次数增加一次，并返回更新后的数量。
- 计数属于装饰性热度数据，不要求强一致。
- 计数读写失败不得让原本成功的合成失败；响应退化为 `hit_count: 1`。
- fallback 不产生配方、不增加次数，也不创建连线。

FastAPI 使用 SQLite `combinations.hit_count` 作为计数来源；更新必须在现有 archive 锁内完成并返回新值。Makers 使用 KV 组合记录中的 `hit_count`；静态 seed 配方第一次被玩家合成时也要建立可累计的 KV 记录。

### 本地配方快照

`ic_recipes` 中每条配方增加：

```json
{
  "hit_count": 8,
  "depth": 4
}
```

- 每次成功合成都会覆盖该配方的 `hit_count`、`depth` 和时间戳。
- 旧版已发现配方没有 `hit_count` 时按 `1` 处理，因为该记录本身已经证明玩家至少合成过一次。
- 缺少 `depth` 的旧配方使用中性的基础连线色，不迁移或清空现有本地数据。
- 不增加轮询、批量查询或页面启动时的全局热度请求。

## 连线关系

连线图只由 `state.recipes` 与 `state.onCanvas` 派生，不使用服务端全量配方数据。

对于配方 `A + B`：

- `A` 与 `B` 不同：画布上每一个 `A` 实例连接每一个 `B` 实例。
- `A` 与 `B` 相同：连接所有不同实例组合，使用 `i < j` 避免自身连接和重复连接。
- 同一无序配方始终使用规范化的配方 key。
- 新增元素、删除元素、清空画布或配方首次记录后，重新协调需要存在的 SVG 路径。
- 拖动元素时只更新现有路径的几何位置，不重建整个路径集合。
- 不设置距离阈值或总连线数量上限。

每条路径使用两个元素中心点和稳定的、由实例 ID 决定的弯曲方向生成二次贝塞尔曲线。稳定曲率可以避免元素轻微移动时曲线左右翻转。

## SVG 结构与层级

在 `#workspace` 内增加一个覆盖整个工作区的 SVG：

```html
<svg class="recipe-links" aria-hidden="true">
  <g class="recipe-link-paths"></g>
</svg>
```

- SVG 位于工作区背景和提示之上、元素卡片之下。
- `pointer-events: none`，不能成为拖放目标。
- 每条关系由一条低透明度底线和一条较短的流动高光组成。
- 路径节点使用稳定 ID 复用，避免拖动期间产生 DOM 垃圾。
- 所有位置更新由单个 `requestAnimationFrame` 调度器合并。
- 工作区尺寸变化时更新 SVG viewBox 和全部路径几何。

## 可替换模块边界

连线效果独立放在：

- `frontend/recipe-links.js`：关系展开、SVG 节点管理、曲线计算、帧调度和公开控制器 API。
- `frontend/recipe-links.css`：连线层级、描边、发光与 reduced-motion 样式。

模块不得直接读取游戏的 `state`、`localStorage`、合成接口或配方图鉴 DOM，也不得修改元素卡片。游戏主逻辑只把普通数据快照传给控制器：

```js
const recipeLinks = window.RECIPE_LINKS.create(workspace);

recipeLinks.sync({
  recipes,
  elements,
});
recipeLinks.scheduleGeometryUpdate(elements);
recipeLinks.clear();
recipeLinks.destroy();
```

公开契约保持渲染技术无关：

- `recipes` 只包含规范化配方 key、输入名、`hit_count` 与 `depth`。
- `elements` 只包含实例 ID、元素名和画布中心坐标，不传递 DOM 引用。
- `sync()` 负责关系集合变化；调用方不接触 SVG path。
- `scheduleGeometryUpdate()` 负责位置变化；调用方不计算曲线。
- `clear()` 移除当前关系但保留控制器。
- `destroy()` 完整释放 SVG、监听器和待执行动画帧。

`app.js` 只在画布增删、移动、配方更新和初始化位置调用这些方法。将来替换为 Canvas、WebGL 或其他开源实现时，只需让新模块实现相同控制器契约，并替换独立的 JS/CSS 资源；合成请求、本地配方、拖放和游戏状态逻辑不需要改动。

## 视觉强度

线条颜色沿用合成反馈的装备稀有度色，由该配方最近保存的 `depth` 决定。全球次数只控制宽度、透明度、发光半径和高光流速。

次数阶段如下：

| 全球次数 | 表现 |
| --- | --- |
| `1–2` | 极细、低透明度、无明显外发光，流动最慢 |
| `3–7` | 线宽和亮度轻微提高，出现很淡的柔光 |
| `8–19` | 关系清晰可见，柔光和流动高光增强 |
| `20–39` | 较强线宽与外发光，高光移动更快 |
| `40+` | 达到最高强度，继续增加次数不再增强 |

实现使用 `clamp(hit_count, 1, 40)` 后的连续、分段插值，而不是只切换五个离散 class。这样第 3、8、20、40 次附近不会出现突兀跳变。

最高强度仍需保持克制：

- 底线宽度不超过约 `2.4px`。
- 主线透明度不超过约 `0.56`。
- 柔光不能覆盖元素文字和图标。
- 夜间效果开启时允许略微降低整体透明度，保持画布层级清楚。

系统启用 `prefers-reduced-motion: reduce` 时停止虚线位移动画，保留静态底线和强度差异。

## 更新时机

`recipe-links.js` 中的独立连线控制器提供以下职责：

- `sync()`：根据当前配方和画布实例创建、复用、更新或删除路径。
- `scheduleGeometryUpdate()`：在下一帧批量更新所有路径坐标。
- `clear()`：清空画布时移除全部路径。
- `destroy()`：卸载连线模块时释放 SVG、监听器和待执行动画帧。

调用时机：

- `spawnOnCanvas()` 后执行 `sync()`。
- `removeCanvasEl()` 后执行 `sync()`。
- `moveCanvasEl()` 后执行 `scheduleGeometryUpdate()`。
- `rememberRecipe()` 后执行 `sync()`，由模块刷新该配方样式。
- 初始化、窗口尺寸变化和响应式布局变化后更新几何。

## 兼容与失败处理

- 无效、缺失或非数字 `hit_count` 统一按 `1`。
- 无效 `depth` 使用中性颜色。
- SVG 或动画 API 不可用时，游戏核心合成与拖放仍可工作。
- 连线模块缺失或初始化失败时，`app.js` 使用空操作控制器继续运行。
- 合成请求失败时不改变本地配方快照或连线。
- 本功能不修改玩家已发现元素、KPI、首发或配方点评的数据语义。

## 测试与验收

自动化测试覆盖：

- FastAPI 与 Makers 成功合成会增加并返回 `hit_count`。
- seed、缓存和动态配方都可以累计次数，fallback 不累计。
- `rememberRecipe()` 保存和更新次数、深度快照，旧数据按 `1` 兼容。
- 未发现配方不产生路径。
- 不同元素多实例产生完整笛卡尔连接。
- 相同元素只产生不重复的实例对。
- 新增、删除、清空和拖动后路径数量与坐标正确。
- `1–2`、`3–7`、`8–19`、`20–39`、`40+` 的强度递增，`40` 次后封顶。
- reduced-motion 下没有流动动画。
- 独立模块测试不依赖游戏全局 `state`，替换为空操作实现后合成和拖放测试仍通过。

浏览器验收覆盖桌面和移动视口，检查：

- 多元素场景能形成用户要求的密集蜘蛛网。
- 连线始终位于元素下方且不拦截拖放。
- 拖动时路径跟随稳定，没有明显跳线或布局位移。
- 低次数连线足够轻微，高次数连线明显更强但不遮挡元素。
